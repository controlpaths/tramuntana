# 5. I2C master and sniffer

[← SPI](04-spi.md) · [Contents](README.md) · [Next: Oscilloscope and AWG →](06-scope-and-awg.md)

## 5.1 Pins and wiring

| Board | J1 | Target |
|---|---|---|
| DIO6 | 15 | SCL |
| DIO7 | 16 | SDA |
| GND | 2 | GND |
| 3V3 | 1 | VCC (if the board powers the target) |

The bus needs pull-ups. Use the target's own, or turn on the board's 4.7 kΩ
pair (see [Hardware](03-hardware.md#34-i2c-pull-ups)).

## 5.2 The master

The I2C master is bit-banged on DIO6/DIO7, open-drain (a line is pulled low
or released, never driven high). It runs from RAM with cycle-counted
timing.

| Setting | Range |
|---|---|
| clock | 1 kHz – 1 MHz (never faster than asked; slow pull-ups make it slower) |
| clock stretching | honoured, up to 10 ms per bit |
| bytes per request | up to 4096 |
| addresses | 7-bit |

It works like the I2CDriver. There are **high-level** operations that do a
complete transaction:

| Operation | On the bus |
|---|---|
| scan | probes 0x08..0x77 (START, address+W, STOP) and lists those that ACK |
| write(addr, data) | START, addr+W, data…, STOP |
| read(addr, n) | START, addr+R, n bytes (NAK on the last), STOP |
| write_read(addr, w, n) | START, addr+W, w…, repeated START, addr+R, n bytes, STOP: the usual register read |

and **low-level primitives** that leave the bus open between calls, so any
sequence a datasheet asks for can be scripted:

| Primitive | On the bus |
|---|---|
| start(addr, read) | START (a repeated START if the bus is already open) + address byte; returns ACK/NAK |
| raw_write(data) | bytes on the open bus, returns how many were ACKed |
| raw_read(n, nack_last) | bytes from the open bus |
| stop() | STOP |
| reset_bus() | up to 9 SCL pulses and a STOP, to free a slave that holds SDA low |

### From the CLI

```bash
tramuntana i2c conf 400k              # 400 kHz, board pull-ups on (--no-pullups to keep them off)
tramuntana i2c scan
tramuntana i2c read 68 75             # register 0x75 of device 0x68 (WHO_AM_I of an MPU-6050)
tramuntana i2c read 68 3b 6           # 6 registers from 0x3b
tramuntana i2c read 50 0010 2         # 16-bit register address (EEPROMs from 24LC32 up)
tramuntana i2c write 68 6b 00         # register 0x6b = 0x00
tramuntana i2c regs 68                # dump registers 0x00..0xff
tramuntana i2c reset                  # bus recovery
```

### From Python

```python
t.i2c.config(400_000, pullups=True)
print([hex(a) for a in t.i2c.scan()])

who = t.i2c.reg_read(0x68, 0x75)              # bytes, write_read(addr, [reg], 1)
t.i2c.reg_write(0x68, 0x6B, b"\x00")          # write(addr, [reg] + data)
raw = t.i2c.write_read(0x76, b"\xf7", 8)      # 8 bytes from register 0xF7

# EEPROM random read with the primitives
t.i2c.start(0x50)                             # True if ACKed
t.i2c.raw_write(b"\x00\x10")                  # 16-bit address 0x0010
t.i2c.start(0x50, read=True)                  # repeated START
data = t.i2c.raw_read(16)                     # NAK on the last byte
t.i2c.stop()
```

A NAK raises `ProtoError` with status 4 (`bus error / NAK`). SCL stuck low
for more than 10 ms gives status 3 (`timeout`): no pull-ups, or an
unpowered target pulling the lines down.

### From the shell

```
i2c conf 400000 on
i2c scan
i2c wrrd 68 1 75          # write 75, repeated START, read 1
i2c write 68 6b 00
i2c start a0              # address byte 0x50 << 1 | W
i2c raw write 00 10
i2c start a1              # repeated START, read
i2c raw read 16
i2c stop
```

Note that the shell's `start` takes the raw **address byte** (address
shifted left, plus the R/W bit), like the I2CDriver.

## 5.3 Diagnosing a bus

1. **Idle levels.** With nothing happening, `dio read` must show DIO6 and
   DIO7 high. Both low: no pull-ups, target unpowered, or a short. SDA low
   and SCL high: a slave stuck mid-byte, so run `i2c reset`.
2. **Scan.** No device: power, pull-ups, SDA/SCL swapped, the device's
   address pins, an enable line. Every address answering: SDA stuck low.
3. **ID register.** Read the part's ID (e.g. BME280 0xD0 → 0x60,
   MPU-6050 0x75 → 0x68) to be sure it is the part you think.
4. **Look at the wire.** Arm the logic analyzer on the START (SDA falling,
   see [Logic analyzer](07-logic-analyzer.md#capturing-this-boards-own-traffic)),
   run the transaction, decode it. A NAK on the address means a wrong
   address or a device that isn't ready (an EEPROM in its write cycle NAKs
   for ~5 ms).
5. **Edges.** If it works at 100 kHz but not at 400 kHz, the rise time is
   too slow. Wire SCL to AIN0 and measure `rise_time_s` with the scope.

The `tramuntana-debug` skill for AI agents has the full I2C playbook:
[`references/i2c.md`](../host/python/tramuntana/skills/tramuntana-debug/references/i2c.md).

## 5.4 The sniffer

The sniffer watches DIO6/DIO7 and reports one message per START…STOP,
repeated STARTs included, in a compact notation:

```
I2C S 68W+ 75+  S 68R+ 71- P
```

`S` START, `68W` address 0x68 write, `+` ACK, `-` NAK, `P` STOP. Here the
master wrote register 0x75, did a repeated START, read 0x71 and NAKed it
(normal for the last byte of a read).

```bash
tramuntana i2c sniff                  # board pull-ups off (the target's are used)
tramuntana i2c sniff --pullups        # turn the board's on while sniffing
```

```python
t.i2c.sniff(True, pullups=False)
for msg in t.events(timeout=10):
    print(msg)                         # I2cMessage: frames, overrun, truncated, t_us
t.i2c.sniff(False)
```

Each `I2cMessage` has a list of `I2cFrame`s (one per START): `address`,
`read`, `ack`, and `data` as `(byte, acked)` pairs. With a
[timeline](12-timeline.md) running, each message carries the board time of
its START.

From the shell: `i2c sniff on [pu]`, `i2c sniff off`.

The sniffer, the SPI sniffer and the logic analyzer share the capture
memory: one at a time.
